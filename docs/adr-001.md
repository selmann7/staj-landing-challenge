# ADR-001: Technical Stack Selection

## Status
Accepted

## Context
For the "Mini Landing Page and Component Library" internship challenge, we need a technical stack that balances performance, developer experience, and professional standards.

## Decision
We decided to use **React**, **TypeScript**, and **SCSS Modules**.

### 1. Why React?
- **Component-Based Architecture**: Ideal for building a reusable component library.
- **Ecosystem**: Rich set of tools and community support.
- **Industry Standard**: React is the most widely used frontend library in professional settings.

### 2. Why TypeScript?
- **Type Safety**: Reduces runtime errors and improves code quality.
- **Developer Experience**: Enhanced autocomplete and documentation within the IDE.
- **Maintainability**: Clearer contracts between components and functions.

### 3. Why SCSS Modules?
- **Scoped Styling**: Prevents global namespace pollution and CSS conflicts.
- **Modern Features**: Variables, mixins, and nesting simplify complex style management.
- **CSS Variables Support**: Perfect for implementing Light/Dark mode transitions.
- **Performance**: Zero runtime overhead compared to CSS-in-JS libraries.

## Consequences
- Requires a compilation step (handled by Vite).
- Developers need to understand SCSS syntax and TypeScript types.
- Provides a robust foundation for a scalable and professional frontend project.
